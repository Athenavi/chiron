## 0. 结论：按收益排序的边界建议

| 批次 | 对象 | 状态 |
|---|---|---|
| 批次 1 | `gateway_router.go`（**最低风险，建议先做**） | **✅ 已完成**：拆成 11 个 `routes_<domain>.go`，`gateway_router.go` 只留 imports + middleware + 装配 |
| 批次 2 · 类型部分 | `runtime.py` 的数据类型 | **✅ 已完成**：`AgentTask` / `AgentEvent` / `ApprovalTicket` / `ApprovalDecision` 移到 `app/agent/runtime_types.py` |
| 批次 2 · 压缩簇 | `runtime.py` 的上下文/消息处理函数簇 | **⏸ 未做**：必须先**按现状重新定界**再动 —— 行数会持续过期，启动前务必重新实测行号，**不要照搬旧数字** |
| — | `AgentRuntime` 本体 | **暂不动**：内聚在「一次 run 的状态机」上，拆它必然触碰行为，不属于本项范围 |

**契约纪律**（三批共同）：**各函数签名与调用点一字不改，仅换文件**；同包（`package api`）⇒ 无需改调用方；
旧路径**保留同名再导出**（逐条 `X as X`，mypy `no-implicit-reexport` 与 ruff isort 同时约束），
**避免改动任何既有 import 路径**。

## 1. 注入面纪律（原文 §2.5，独立于拆分本身，**长期有效**）

- 拆分**不得**扩大可注入面：新增模块只承接**已经存在**的依赖，不引入新的全局/单例/注册表。
- 「测试要能替换依赖」靠**参数显式传递**，不靠 `'x' in locals()` 之类的探测。
- 每次拆分都要重新量**注入面引用数**；引用数上升即为**回退信号**。

## 2. 两个已记录的坑（省下重踩的时间）

- **`goimports` 在整包编译不过时不会补 import**（它需要包可加载）⇒ 拆完正是编译不过的状态，它会**静默无输出**。
  改用「按限定符静态推导 import + `go build` 兜底」。
- `runtime.py` 的再导出必须是**逐条 `X as X`**；写成一行或合并多行都会被 mypy 或 ruff 其中一方判红。
