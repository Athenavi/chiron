# Chiron 与 Reasonix 2.x 的 UI/UX 差距分析（摘要）

> **全文已归档** → [docs/archive/reasonix-ui-ux-gap-analysis.md](archive/reasonix-ui-ux-gap-analysis.md)（2026-10-09）。
> 本页只保留**结论 + 行动项清单（含状态）+ 章节去向**；量表、逐条证据与复现步骤在归档全文里。

## 0. 结论摘要（原文 §0，逐条）

| # | 结论 | 强度 |
|---|---|---|
| 1 | **Chiron 的 UI 静态纪律不落后，甚至更干净**：门禁（z-index / 主题 / 动效 / i18n / i18n-keys / a11y / 主题键集）基线**全部为空**、`build` 阻断 | 【实测】 |
| 2 | **transcript 的「法」两边都有，只是放的地方不同**：Chiron 在 [transcript 契约](transcript-contract.md) + 7 个纯几何模块；2.x 在 `styles/LAYOUT.md` | 【文档】 |
| 3 | **真正的差距是「验证」**：Chiron **零浏览器 / e2e 测试**，测试/源码字节比 **0.11×**；2.x SPA **0.77×**（含 179 个 interaction test + `MockPort` + 16 条 census 不变量） | 【实测】 |
| 4 | **契约与实现曾不一致**：契约规定「唯一写 `scrollTop` 的模块」，而 `ChatView.vue` 有 3 处直写 —— **其中 2 处属 transcript，已修并落地源码级门禁**；第 3 处写的是另一个容器（`.unified-list`） | 【枚举】 |
| 5 | **最大的可搬运机制是「接缝」，不是工具**：2.x 用一个 `AgentPort` 契约 + `MockPort` 把内核换成可脚本化的假实现 ⇒ 才可能有 179 个 DOM 级交互测试。**补它不需要新依赖** | 【枚举】 |
| 6 | **2.x 的文档分层值得学**：`app.css` 不带注释，理由全写在 `styles/LAYOUT.md`；而 Chiron 的知识散在 `style.css` 注释与组件注释里 | 【枚举】 |

## 2. 一句话总结

Chiron 在**静态 UI 纪律**与 **transcript 契约**上并不落后：2.x 的渲染法写在 `styles/LAYOUT.md`、
Chiron 的写在 [transcript 契约](transcript-contract.md) 里，两边都算「有法」。
差距集中在两处：**（a）契约没被实现完全遵守**（已修并加门禁；另一条保留为**已文档化的差异**）、
**（b）契约的验证没有机械化**（0 浏览器测试、测试/源码 0.11× vs 0.77×）。
