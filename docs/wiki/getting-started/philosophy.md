# 设计理念

> **权威来源**：规划文件 `vendor/规划.md` §6（**不做清单**）与各契约文档。
> 本页是「为什么这么定」的导读，**不是新的规范**。

## 北极星

**超越 deepseek-harness** —— 但「超越」有严格判据：

- **对外可核实的行为**才算数，**不是「有对应模块」**。每条切口落地时必须给出：
  **可复现命令 + 期望输出 + 反例**（没做时会怎样）。
- **只有「同一层」才可比**：agent 循环 / 子 agent / 事件契约 / 执行隔离 / 可审计性。
  交付形态与 UI 不可比，**不列入差距**。
- **平台面不与单机对标**：多租户、配额、计费、多副本协调是 Chiron 独有的一段。

## 三条工程纪律

1. **不引新依赖**去追平一个能力 —— 优先「把已经写对的东西写成类型、测试或文档」。
2. **不造事件凑齐**：没有真实状态可上报的机制就**结案不做**（例如「阶段（Phase）事件」）。
3. **UI/UX 差距是文档化，不是渲染重写** —— 已文档化的差异**不为了对齐而重构**。

## 证据阶梯（写文档时按这个标强度）

**【枚举】** 逐文件/逐符号读出 < **【文档】** 读契约原文 < **【grep】** 全仓检索 < **【实测】** 本机跑出来的结果。

**没实测过的结论必须标出来**，不许当成事实引用 —— 差距分析里专门有一节「不确定 / 未验证」。

## 明确不做的事（与规划 §6 一致）

| 不做 | 理由 |
|---|---|
| **Electron 桌面** | 对标项目的 `desktop/` 是十几 MB + 独立 host + 签名自更新；与「多租户 SaaS + Web」冲突，收益全在本地分发 |
| **改写成纯 Go** | 对标项目用 Go 是为了**单静态二进制分发**；Chiron 的引擎价值在被租户共享的 Python 生态（MCP / RAG / 工具），**语言不是能力** |
| **照搬 TUI** | 那是本地交互取舍 |
| **引 LangGraph / LangSmith** | 对标项目自己也是自研内核，没有引入 |
| **引向量库**（再引一套） | Chiron 已有 Milvus；对标项目的记忆检索是 Markdown + BM25，**这不是差距** |
| **照搬 `bestof` / worktree 类能力** | 建立在「本地 git 工作区」形态上，与多租户 SaaS 不同构 |

## 还有一条容易忽略的纪律

**迁移链必须只有一个 head** —— 这是 CI 的一个 job 在守的（`schema`），
不是风格问题：多 head 会让部署时的 `upgrade head` 变成歧义操作。
